# Station Card (Carvaan trains app) — context for agents

This file is the hand-off from the sessions that built the app (Oct 2026). Read it fully before
changing anything. It covers what the app is, how every piece is produced, the decisions Kushal has
made, and what is still open. Kushal is the product owner and designer; they review on a real iPhone.

## 1. Working rules (from Kushal, non-negotiable)

- **No product or design decisions without asking.** Sizes, colours, spacing, animation, interaction,
  what is visible: if it is not specified, ask. Do not "improve" things that were not requested.
- **Figma is the single source of truth for the home screen** (file `qDwXSSgvF4FpIEloyt5zvg`, node
  `171:218`, "Decade-iter"). Use its exact values; loop until pixel-perfect. Exception: the station
  card itself was designed in code before the Figma screen existed and must not be changed to match it.
- **Never add visible UI, test modes or debug UI** in the app. "Add logs" means console logs only.
- **Incremental over rewrite.** Targeted changes; discuss design forks first.
- **Auto-rebuild after every code change** (`xcodebuild … -destination 'generic/platform=iOS Simulator' build`)
  and report `BUILD SUCCEEDED` / errors. Do **not** launch the iOS Simulator yourself; Kushal runs the
  app from Xcode on their iPhone. "open xcode" = `open -a Xcode StationCard.xcodeproj`.
- **Performance is a feature**: 60 fps, no frame cap, the card stays native SwiftUI, only the train is
  a web layer. Scenes contain no people. "Evening" is a distinct phase from "sunset".
- Keep replies short: lead with the outcome ("BUILD SUCCEEDED, just Run"), then what changed.
- Wording quirks: "arc" = the stone arch; "themes" = the day/evening/sunset/night phases;
  "variations"/"trains" = liveries; "0.2x smaller" meant scale by 0.8.

## 2. What the app is

A SwiftUI iPhone app (`com.kushal.stationcard`, iOS 17, portrait only, project generated by
**xcodegen** from `project.yml` — run `xcodegen generate` whenever files are added/renamed under
`Resources/` or `Sources/`). One screen (`HomeScreen`) with a header, a 3×2 tile grid and a vertical
stack of **station cards**. Each card is a white rounded panel with a stone arch at the top, a station
code engraved on the arch's crown plaque, a two-line station title inside the arch opening, and a live
3D train scene (three.js in a transparent `WKWebView`) running along the bottom, in front of the arch.

```
Sources/
  StationCardApp.swift   app entry; pre-warms the first web views at launch
  ContentView.swift      DayPhase (clock rule), Cards (the card list), StationCard view, CardsListView (old, unused)

  TrainWebView.swift     TrainWebViewHost (one WKWebView per card, capped), TrainWebView, app:// scheme handler
  LavaClip.swift         .lava decoder (frames composed to CGImages); LavaIconView.swift  poster + play-once view
Resources/
  arch-<phase>@3x.png          stone arch, transparent, 1056×1001 (rendered from tools/arch/arch.html)
  placeholder-<phase>@2x.png   first frame of the scene, transparent, 640×400 (shown until the page draws)
  figma/tile-*.png, carvaan-logo   home-screen assets exported from Figma (tile PNGs are the lava sources)
  lava/tile-*.lava                 animated tile icons (see §4)

                                   PostScript name "BusinessSerifTrial-TextRegular")
```

## 3. The station card (`StationCard` in ContentView.swift)

- Design size **320 × 400 pt**; everything scales with `scale = width / 320`. The home screen passes
  `width = 374 * s` (Figma card width) where `s = screenWidth / 390`.
- ZStack(.top) order: arch image → station code text → `TrainWebView` → placeholder image (until the
  page reports ready) → title text. The scene is drawn **in front of** the arch so the train and masts
  overlap the capitals.
- Arch: `archSize = 301 × (301·1001/1056)` pt, centred, touching the top edge (94 % of the card width).
  `.shadow(black 0.10 day / 0.25 night, radius 8, x 4, y 7)` = a subtle drop shadow matching the
  render's key light (upper-left, in front). `plaqueCenterY = archSize.height · 38/1001` (measured from
  the asset; the ring top never moved so row 38 has held through every re-render).
- Station code: Inter Medium 10 pt, tracking 1.4, colour `#6E6E6E` (night `#B4B9C8`), centred on the plaque.
- Title: Business Serif 26 pt, line spacing 5, centred, block height 70 centred at `0.51 × archHeight`
  (from Kushal's mock); colour `#111111`, white at night.
- Card background white; **night phase only** darkens the card to `#2C0D10`. App background `#F7F7F5`.
- Corner radius 28 pt continuous; two soft shadows.
- The train stage inside the page is **full card width, 200/320 of the width tall**, anchored at the
  bottom (`.stage { height: 62.5vw }`). The scene was scaled to 0.8× by reducing the stage height; the
  track was then lengthened so it still runs edge to edge (see §5).

History of the card size: 320×380 → 320×400 when the arch was added (Kushal: "increase card height by
a very small amount").

## 4. Home screen (`HomeScreen.swift`)

Implemented from Figma node 171:218 with every value from the design (390 pt wide design, `s` scale):
- Header: CARVAAN logo 155.167×25.093 at the top, accessibility capsule button at the right (65 pt from top).
- 3×2 tile grid: 360.667×177 at (15, 121), gaps 11×13, tiles `#FAFAF8` radius 27, image + label
  (Light Text Trial 17/25, `#424242`, label top 32 pt above the tile bottom). `HomeTile.all` holds each
  tile's image name, size, offset, label; tile 1 crops its image.
- Cards: `LazyVStack` of `StationCard`s. The first card sits exactly where Figma places the single card
  (374 wide, its bottom 76 pt above the screen bottom); the rest follow with a **16 pt gap** (the gap the
  earlier cards list used). The whole screen is a `ScrollView`; content height is computed from the card
  count. Off-screen cards pause their render loop (`isActive && isVisible`).
- Figma SVG exports use CSS `var()` fills that Apple can't render — inline the hex when exporting.
- **Tile icons are `.lava` clips** (`Resources/lava/<tile>.lava`, 192×192, 36 frames @ 30 fps, 16 px cells),
  made from the Figma renders with `~/airbnbIcons/iconstrials/lava-encode.py --axis y --frames 36 --size 192
  --cell 16` (a card turn about the vertical axis; renders on white are keyed automatically).
  `Sources/LavaClip.swift` decodes the container (RIFF → PNG keyframe + atlas → FRAM patch table, raw
  DEFLATE via Compression) and composes every frame into a CGImage once; `Sources/LavaIconView.swift`
  shows frame 0 as the poster and plays the clip once per `play` change with a CADisplayLink (Reduce
  Motion → poster only). `HomeTileView` follows the Airbnb pattern from the write-up: entry clip once on
  appear, staggered 400 ms + 80 ms × tile index, replay 150 ms after a tap. Figma frame/crop/offset unchanged;
  the original PNGs stay in `Resources/figma/` as the encoder's source.

## 5. The train scene (`web/index.html`)

Query parameters: `phase=day|evening|sunset|night` (else the clock rule), `livery=<key>` (default red),
`station=1` (platform variant with canopy, second track, train stops; **not used by any card today**),
`capture=1` (pins the stage to 320×200 at the top-left and freezes time at 0, for placeholders),
`bg=<css colour>` (with capture, for matting), `t=<seconds>` (freezes the scene at that moment, for
livery checks), `bake=1` (see bake), `night=1` (legacy).

Scene: a diorama slab of ballast and track (`BL = 22` units long so its rounded ends stay out of frame
at the wide stage; `FH = 8.75` places the catenary masts and street lamps at the frame edges), a level
crossing with barriers/lamps/signs (Japanese-style crossing furniture, Indian-style train), grass, a
parrot that lands on the wire between trains, overhead wire with sag. Camera `PerspectiveCamera(30)` at
`(0, 11.5, 18.5)` looking at `(0, 1.7, 0)`. The train (`CARS = loco, slr, gs, sl, sl, pc, ac, ac2, slr`)
enters from the right every `PERIOD` seconds at `SPEED = 11`; the crossing closes before it and opens
after. Lighting per phase; at night/sunset windows glow via an emissive mask drawn by the same texture
code with `EMI = true`.

**Liveries** (`LIVERIES` table near the top of the file): every skin is painted on the same side layout
(fractions of the side height: roof lip 0–0.04, upper band 0.10–0.26 where the coach code sits, windows
0.31–0.55, lower band 0.60–0.86, underframe 0.86–1). Fields: `base/baseD`, `bands [[y0,y1,colour,shadow]]`,
`stripes [[y, px, colour]]` (negative px = above y), `door/doorD/frame`, `label`, `roof`, `cap` (loco cab
roof), `cow` (loco cowcatcher hex), optional `pattern(g,w,h)` for vinyl artwork (Duronto flowers,
Humsafar waves, Tejas sweep; skipped on the glow mask). 24 keys:
`red, blue` (the original cream body with red/royal-blue bands — keep as they are), `icfblue, utkrisht,
brick, rajdhani, shatabdi, garibrath, duronto, janshatabdi, deendayalu, mahamana, lhbred, lhbdeendayalu,
lhbblue, gatimaan, humsafar, tejas, antyodaya, uday, doubledecker, garibrathlhb, vistadome, amritbharat`.
Colours are approximations from written descriptions (no source gives exact values); Kushal has not yet
reviewed them on device. Least certain: janshatabdi, mahamana, vistadome, garibrathlhb.

**Bake**: `baked/<phase>-<station>-<livery>.json` + PNGs are the painted canvas textures captured once via
`?bake=1` against a small bake server, so the page skips painting at startup; a missing bake falls back
to painting live. Bakes exist only for the original red/blue liveries; new liveries paint live (fine).

`window.setPaused(bool)` is called by the app to stop the loop off-screen. The page posts `ready` to the
app after its first frame; the app then fades the web view in over the placeholder.

## 7. Web view hosting (`TrainWebView.swift`)

`TrainWebViewHost.host(id:)` keeps one `WKWebView` per card id. Each is a WebKit process with a WebGL
scene, so hosts are capped at **`maxLive = 4`**: when a new one is needed, the least-recently-used
*inactive* host (card scrolled away) is dropped and rebuilt when it scrolls back in (the placeholder
covers the reload). Visible hosts are never dropped. The app pre-warms the first `maxLive` cards at
launch. Pages are served through a custom `app://card/` URL scheme from the bundled `web/` folder.

## 8. Phases and the clock

`DayPhase.at(date)` and the page's `PHASE` resolver use the same rule: day until 16:30, evening until
17:45, sunset until 18:45, night until 06:00 (local time). Both were temporarily pinned to `day` during
development and **restored on the first commit** (Kushal: restore "when we commit anything").

## 9. The stone arch (`tools/arch/arch.html`)

A Corinthian arch modelled in three.js from two reference images Kushal supplied: a white 3D render of a
classical arch (stepped archivolt with a coffer band, two chamfered voussoir blocks at 37° above the
springing, chamfered imposts, panelled pier heads, Corinthian capitals with abacus, fleuron, volutes, two
tiers of acanthus, astragal and shaft stub) and a card mock-up with the arch spanning ~94 % of the card,
touching the top, station code on the crown plaque, title centred in the opening.

Key constants (all in arch.html): ring profile outer radius 1.280 / inner 1.000 (fascia, step, coffer
floor 1.128–1.232 with radial ribs at `PITCH` 4.6°, rim, fillet), `BACK = -0.42` depth, `PLAQUE_HALF`
0.235 rad, voussoir blocks at `BLOCK_ANG` 37° ± 8.6°, imposts at x ±1.14, y −0.065, pier heads below with
sunken panels, **`PIER_EXT = 0.42`** (extra pier height Kushal asked for in two steps: "increase the
pillars height" then "a little more"), capital groups at `(±1.14, −0.305 − PIER_EXT)` scaled
(0.58, 0.72, 0.8). Camera `PerspectiveCamera(14)` at (0, 1.35, 15.5) looking at (0, 0.21, 0). Lighting
per phase mirrors the card scene; GTAO ambient occlusion; stone material `#f4f3f0` with a speckle map.
Params: `?phase=…`, `?bg=black|white` (matte passes), `?ao=0`, `?view=cap` (zoom on a capital).

History of its proportions: first version was "too thick" → ring outer 1.38 → 1.28 ("a bit more thin
overall"), pillars thinned, then lengthened. Kushal rejected shrinking the arch to clear the scene ("you
make it so small now"); the fix was the full width + taller card + scene in front.

**Render pipeline** (macOS only — needs Google Chrome and python3 with numpy + Pillow):
1. `cd tools/arch && python3 -m http.server 8767 &`
2. `tools/arch/render-arch.sh` — headless Chrome (`--headless=new --use-angle=metal`) renders each phase on
   black and on white at 3200×2200, then `matte.py` difference-mattes them (alpha from the two renders,
   straight colour from the black render), crops to the canvas height, crops a bbox symmetric about the
   centre so the arch stays centred, and downsamples (premultiplied LANCZOS) to 1056 px wide →
   `Resources/arch-<phase>@3x.png`. It prints the size.
3. If the height changed, update `StationCard.archSize` (`301 * H / 1056`) and `plaqueCenterY`
   (`38 / H`); if the ring itself changed, re-measure the plaque row from the asset.

## 10. Placeholders

`tools/placeholders.sh`: the page in `capture=1` mode at 320×200 @2x, on black and on white, difference
matted → `Resources/placeholder-<phase>@2x.png` (640×400). The train is not in the first frame, so one
per phase is enough (a per-livery set was made and then removed). Re-capture whenever the scene's first
frame changes (stage size, track, furniture). Needs `web/` served on :8768.

## 11. Livery checks

`tools/livery-sheet.sh [t]` renders every livery frozen at `t` seconds (default 7.2 = coaches in frame;
2.0 = loco in frame) and writes `tools/livery-sheet.png`.
